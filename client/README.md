# AJinOS

Windows 桌面客户端 + 同源本地网页（macOS / Linux 支持本地网页模式与源码启动）。工作台、对话、能力与沙箱共用「瓷白蓝紫」日间主题与「深蓝灰」夜间主题。工作台默认打开流转概览，通过实际状态展示入口触发、总管路由与 Hub、项目执行和本人介入。

## 启动

Windows x64 用户可以双击 `AJinOS-Setup-x64.exe` 安装，随后从开始菜单打开「AJinOS」。安装包包含 Electron、Node.js 24、客户端后台和 Hub / Worker。首次打开只创建默认项目「AJinOS」，用于协助配置软件。运行 Codex 或 Claude 任务需要安装并登录对应的命令行工具。

飞书私聊也可通过配套插件进入同一自动识别链路，支持自然语言、图片和图文，回复消息继续原话题，不要求项目前缀。图片实际读取后，事实和本机原图路径随任务资料保留。接入与限制见 [网关架构](../docs/studio-architecture.md)。

从源码运行需要 Node.js 24+。首次安装：

```bash
cd client
npm ci
npm run setup:desktop
```

双击 `client/launch.vbs` 打开桌面客户端，或在此目录运行 `npm run desktop`。网页入口默认是 <http://127.0.0.1:3360>。只需要网页时运行 `npm start`；桌面和网页启动命令二选一，桌面启动后仍可用浏览器访问同一个入口。

关闭桌面窗口会收进系统托盘，任务继续运行。右击托盘 →「退出客户端与自管中台」才退出。只停止客户端自己启动的 Hub / Worker，不停止外部引擎；正在执行的 Agent 按原引擎的恢复机制保留。网页模式用 Ctrl+C 退出。

默认数据目录为 `%USERPROFILE%\.agent-autoloop-studio`，与原来的 `.agent-autoloop` 隔离。`STUDIO_HOME`、`STUDIO_PORT` 可覆盖目录和网页端口；`STUDIO_NODE` 可为桌面端指定 Node 路径。`STUDIO_CONNECT_ONLY=1` 只连接指定数据目录中的既有引擎，不启动它；`STUDIO_AUTOSTART=1` 让启动时自动启动自管引擎（默认不启动，由页面按钮决定）。不要同时启动两个管理同一数据目录的客户端服务；多窗口直接访问同一网页入口。

左侧栏底部的引擎图标可启动 Studio 自管引擎，运行时点击同一个图标并确认即可停止。重启可以在「能力与沙箱」→「运行环境与引擎」操作。停止期间仍可查看设置，已启动的 Agent 可继续执行。版本更新需要引擎已启动并确认任务空闲。

## 页面能力

- **对话**默认打开 AJinOS 总管。问「今日简报」或用 `/ask` 直接读取状态。明确的单项目请求可直接派发，项目未确定时到「待我处理」选择。`/plan` 生成 DAG 草案，本人确认后按依赖启动。需要手动指定项目、流程、模型或路由方式时，点输入框的「高级覆盖」。
- **待我处理**汇总待拍板、待验收和未解决的入站请求。最近事项支持项目、状态和正文筛选，也可置顶。进入 Thread 后续聊沿用原话题绑定。「展开详情」可查看验收依据、执行轮次、独立校验和输出，并按当前工单状态操作。草稿及已上传图片按对话保留在当前窗口。
- **工作台**提供流转概览、工单看板和 DAG 协作计划。点击画布工单或使用「跟踪任务」定位流转路径、查看执行依据和验收。看板可按分类、项目和状态筛选，也可切换到列表。
- **能力与沙箱**默认打开「项目领地（沙箱）」。在「消息渠道」可打开内置的桌面消息接收器、设置系统通知提醒。点「添加其他来源」选择飞书后才会显示飞书卡片：缺少 CLI 时卡片给出安装指引，CLI 可用但未授权时可直接扫码授权。授权后可开启私聊通知，或点「添加采集群」按群名搜索并选中群聊，再选择采集范围。「测试读取」最多预览一条匹配消息，点「启用采集」后才保存群和定时规则。首次启用默认在 09:30–18:30 每 5 分钟采集一次，可在「扫描设置」调整周期。已启用的群可以编辑范围、选择要匹配的群成员和机器人，或移出采集。本人及机器人发出的消息会跳过。飞书卡片可以从页面移除，移除前会说明将停用私聊通知和群聊采集，之后可重新接入。

「添加其他来源」目前可接入飞书，其他平台和自定义 HTTP 来源暂未开放。飞书凭据和采集设置保存在本机私有配置中。

空地址和 `#overview` 打开流转概览，`#tasks` 打开工单看板，`#tasks/plans` 打开 DAG 协作计划。`#projects`、`#inbox` 和 `#messages/<topic>` 仍会打开原位置。「运行环境与引擎」提供三种主题模式，左侧导航轨底部可直接切换日夜。

在工作台或能力与沙箱，点击右下角聊天图标或按 `Alt+Shift+A`，即可就地与 AJinOS 总管沟通。悬浮窗口与完整对话共用总管记录和草稿，支持 `/ask`、`/plan` 和自动分流。展开工单详情时，聊天按钮向左避让。按 `Escape` 收起聊天。

左侧栏底部有引擎、外观、刷新和版本四个图标。外观可选白天、夜间和跟随系统。刷新在桌面端绕过缓存，运行中的任务会继续执行，编辑中的表单需先保存或取消。发现新版本时，版本图标会有提示点。源码版支持查看提交和历史版本回滚，浏览器可查看版本。

## 全项目设计提示词

### 把复杂留给系统

复杂应该留给系统。做设计取舍时，用户体验优先。按这条原则审查整个项目的界面和用户流程，请担任方案、文案和交互顾问。沿着用户实际做事的顺序，逐项检查：

- 系统能判断的，自动判断。
- 此刻没用的，就不出现。
- 能替人做的，就直接做。
- 同一件事，处处一样，入口、文案、操作和反馈都一致。
- 按下去立即有回应，可逆的操作再按能收回，或就地撤销。
- 尽量不打断用户手上的事，保留正在编辑的内容和操作位置。
- 常用操作容易完成，会丢东西的操作难以误触。
- 让界面自己说清楚当前是什么状态、能做什么、下一步去哪。

### 把每次状态变化交代清楚

把全项目的动效做到苹果产品那样细腻、流畅。自己走查全项目，请 Gemini 一起看方案、文案和交互，审完直接改。按状态变化走查，从页面切换到图标、数字和勾选，覆盖出现、消失、移动、缩放、内容或图标切换、数值更新、按下、悬停、加载、完成和出错。每次变化都问一句：用户看得懂刚才发生了什么吗？

- 用动效说明东西从哪来、到哪去、和什么有关，每个动作都要有交代。
- 同类变化沿用同一套曲线和节奏，统一项目已有的动效。
- 快、轻、克制，高频操作更快，能省的动效就省。
- 拖动和调整大小直接跟手。动画途中再次操作时，从当前状态自然接上。
- 只动必要的元素，用实际操作测帧率和掉帧，长列表和长内容也要稳定流畅。
- 检查抖动、闪烁、意外重排和溢出，尊重系统的「减少动态效果」设置。
- 手机、窄窗口、宽屏和深浅色都要亲自验证。

直接修好走查发现的问题。改完亲手走一遍受影响的用户流程，确认通过后，请独立审查。修好复审发现的问题并重新验证，再按仓库约定完成检查、合并和上线。

## 桌面更新与回滚

带更新源的 Windows 安装版启动后会检查 GitHub Release，此后每 30 分钟检查一次。发现更高的稳定版后，顶部显示「发现新版本」。客户端通过已登录的 GitHub CLI 下载安装包，校验大小和 SHA-256，等表单和自管 Hub 空闲后静默安装并重新打开。更新沿用原数据目录。首次启用需要覆盖安装带更新源的版本，并在本机登录有该仓库读取权限的 GitHub CLI。安装包只记录更新仓库名，凭据由本机 GitHub CLI 管理。

构建带更新源的版本时运行 `npm run package:windows -- --update-repo owner/repo`。产物为 `dist/autoupdate/AJinOS-Setup-x64.exe`。在检查通过的干净发布标签上构建，再将该 EXE 作为同一标签的稳定 GitHub Release 附件上传。Windows 安装版可通过覆盖安装指定版本修复。下面的 Git 更新与回滚适用于源码版。

通过 `launch.vbs` / `launch.ps1` 或 `npm run desktop` 启动稳定的 `desktop-launch.mjs`，由它启动当前 Electron 与后台。首次以当前分支的跟踪 remote 为更新源（没有跟踪时用 origin）；只接受包含 Studio 启动器的稳定 `vX.Y.Z` 标签，更新说明优先读标签注释，否则读该版本提交。Git 凭据仍由现有凭据管理器提供，不写入更新元数据。无发布标签、检查失败、无历史版本都显示真实状态。

更新克隆到数据目录下 `desktop-versions/releases/<commit>`，运行真实 npm 安装、Electron 运行环境安装、构建、检查与临时目录启动探测。原工作目录及其未提交文件不覆盖；更新前版本保留在历史记录。安装好后再确认自管引擎空闲；请求、画像分析、执行中、排队及状态不明任务会阻止切换。外部管理的引擎不能通过这里更新。版本切换关闭自管后台并重启整个桌面进程，只有界面初始化成功且 Hub 已连接才确认；启动失败会清理新进程并恢复上个版本。

回滚只切换程序，继续使用当前项目、规则、消息与事实日志，不撤销业务记录。原开发目录仍可被本人修改，因此历史条目会注明“原工作目录”。更新不是生产发布：客户端不创建、删除或移动远端标签。源码安装更新器需要 Git、Node 24+、npm 和发布源访问权限。

人工验收：`python tests/desktop-update-e2e.py` 在临时本地仓库创建测试标签，用真实 Electron 完成安装、重启、回滚和坏版本恢复，不发布远端版本、不使用日常数据目录。`python tests/theme-ui.py` 验证日夜、跟随系统、刷新和主要弹窗；可传入截图目录。Windows 已运行；macOS/Linux 的桌面生命周期仍需真机验收。

顶部菜单提供 4 个一级页：**工作台**、**任务中心**、**项目空间**和**系统配置**。工作台各区块旁的「管理 ↗ / 查看 ↗」和底部「规则与定时」直接跳转到对应一级页或系统配置子页，不再嵌套大型管理弹窗；旧 hash 链接（`#inbox`、`#rules`、`#connections`、`#agents`、`#feishu-groups` 等）继续兼容映射。

| 页面 / 模块  | 操作与状态                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------------- |
| 工作台       | 全部业务项目、项目网关、Codex 两档方案、共享容量、排队原因、当前任务与输出；全局/跟踪视图、真实状态变化动效 |
| 任务中心     | 统一汇聚「待我处理」、看板/列表与「总管统筹」（全局零消耗简报、进度问答、多工单 DAG 协作计划）；详情支持验收并同步 Hub 原生工单及提炼长期记忆 |
| 项目空间     | 选择工作目录即可添加项目。详情可查看画像和目录大小，修改项目权限、并行数、话题上下文和 GitHub 设置 |
| 系统配置     | 左侧分组菜单统一收口：项目识别网关（支持切换执行器/模型/思考强度）、长期记忆档案、规则与定时、消息渠道、运行环境与引擎、执行器导入、引擎日志、高级 JSON 与版本 |

通用表单覆盖常用协议字段，高级 JSON 编辑器保留全部原生字段（包括 `elsewhere` 外部定时任务登记）。配置先由原项目 `parseRules` 验证，再写入；保存检查版本冲突，并保留上一份 `studio.previous.json`。规则热更新，容量和通道连接变更需重启。

## 第一次体验

在项目空间选择默认项目「AJinOS」，再发一条任务，例如“帮我检查当前配置，把本机最大并发改成 3”。随 EXE 安装的 MCP 会读配置、校验并提交建议。打开「系统配置 → 高级 JSON 与版本」，查看改动前后的设置，确认后点「应用配置」。需要重启引擎的设置可在运行环境页操作。

安装版自带运行 MCP 的 Node 和脚本，最终用户通过桌面界面完成操作。内置项目使用本机已安装并登录的 Codex CLI，由 Studio 自管引擎在启动该项目的任务时接入 MCP。已经初始化的数据目录保留原有项目列表。

首页可选择任一项目查看该项目的任务与配置，点击「新建任务」经项目网关提交。无法确定归属的请求会保留在网关，手动选择项目后继续；网络失败则保留原消息原样重试。需要查看局部时选择任务并点击「跟踪当前任务」。

接入实际项目：在「项目空间」选择本机目录，系统按文件夹命名并生成基础规则。画像和任务沿用「系统配置 → 执行器与模型」的规划、执行配置，留空时沿用本机 CLI 默认模型。并行执行数受 Worker 容量及规则并发限制，实际支持范围以本机 CLI/账号为准。

新增事件来源的密钥，可使用原 CLI `key new source <来源编号>`（进程环境中的 `AGENT_AUTOLOOP_HOME` 和 `AGENT_AUTOLOOP_RULES` 必须指向 Studio 数据目录）。这会生成秘密，交给相应调用方的安全凭据机制；不要写入规则、代码或截图。通道连接由客户端自动管理其 Hub 密钥，平台参数保存在该数据目录的私有 `config.json`，不会回显或随规则导出。

## 项目识别与上下文

项目预分析、首次会话识别与模型分档见 [架构分层图与说明](../docs/studio-architecture.md)。项目空间可分析画像、更新画像和添加流程，网关弹窗可查看真实识别提示词、开关智能识别和维护拦截词。

识别渠道默认复用用户已登录的 Claude Code、Codex 或 Antigravity（ACP）执行器，模型留空时沿用本机 CLI 默认，也可在网关或三角色设置中手动覆盖；简单/复杂任务分档同样可在配置中按需指定执行器与模型，或手动指定任务等级。已有话题、任务或已登记的 CLI 会话按绑定续接，项目标识不会被正文覆盖。歧义、模型错误或失效标识不会直接派发；演示和普通流程保留原执行器。已有话题没有等级时沿原规则继续。

消息在 `studio.db` 中以消息 ID 去重，话题持久绑定项目、流程和执行等级。事件 `subject = 项目编号:话题编号`，项目规则使用 `parallel` 建立事项隔离。`resume` 决定普通新事件是否续接 CLI 会话；回答和定时复查依照原引擎回到原事项。更换项目目录必须更换规则名，避免错误继承旧目录的会话。能否恢复完整 CLI 上下文，仍取决于所选执行器的 session/resume 支持。

## 可观测性的范围

界面来自 `/v1/state` 和 `/v1/stream`，不是随机进度动画。断连显示离线并保留最后快照。任务详情读取原引擎 `why` 事实以及本机 Worker 的 stdout/stderr（每文件末尾 24 KB，最近三次尝试），不展示内部推理链。远端 Worker 的本地输出不在本机，界面会说明；进程用量未上报时不会伪造。

业务项目全部列出；消息接入使用 `role: "integration"` 登记，不参与新项目识别，原有话题与规则仍保留。外部可信规则的目录唯一匹配项目目录时，展示层计入该项目，目录歧义时保持未归属；该关联不改变派发、暂停或删除规则。

执行数、排队数和待答复数来自真实状态。两档模型共享对应 Worker 的容量，不把各执行配置的容量相加。仅客户端自己启动的引擎显示已应用容量；仅连接模式显示配置容量和实际容量未确认。状态不明不显示为空闲，排队列表按等待时长展示，不伪称领取顺序或预计完成时间。

任务输出约每 2 秒刷新，展示已上报反馈而非内部推理链。已观察到的本机领取配置只保存显示字段（模型、推理强度、Worker），不会把 Job 中的 token、prompt 或命令送进页面。尚未观察到的历史配置明确区分当前配置与未记录。人工答复关联事项与规则，不按规则名绑定到任意一轮任务。

动效只随新任务及真实阶段变化移动一次。历史加载、重复快照和重连不重放；离线、后台标签页、暂停和系统减少动态效果时停止。支持全局和当前任务路径视图；不依赖 WebGL 或 CDN，不展示虚构进度百分比。区域间方向线常驻，连接具体项目与模型卡片并避开无关区域。任务路径栏显示来源、项目、模型、已走过的步骤和当前位置；执行中的节点显示活动标记。用户可手动回放本轮已经走过的路径，光点和状态栏明确标注“回放”，不重新执行任务，不改变真实状态。

## 本地安全与验证

HTTP 仅绑定 `127.0.0.1`，严格校验 Host / Origin，接口要求同源 HttpOnly Cookie，修改操作另需自定义请求头。界面拿不到 Hub owner/source/worker 密钥。Electron 关闭 Node integration，启用 sandbox/context isolation，拒绝外部导航和权限申请。它面向可信本机用户，不提供多用户远程访问。

```powershell
npm run build
npm run check
npm test
```

已有工作台服务运行时，可用 `python tests/management-ui.py http://127.0.0.1:3360` 验证画布管理入口、嵌套表单与顶部菜单。测试拦截所有写请求，配置保存仅在浏览器中模拟。用 `python tests/pending-tasks-ui.py` 验证「待你处理」的分栏、答复和小窗口布局，脚本会启动独立的临时工作台和演示执行器。两项测试均需本机 Python Playwright 和 Edge。

测试覆盖项目歧义、话题隔离、非法配置、配置冲突、消息重放、HTTP 权限边界、SSE、真实 Hub/Worker 执行、人工回答、定时续办、受控重启与通道撤销。测试使用独立临时数据目录及随机端口；不会调用模型或发送真实通知。

## 建筑样式与模型预设

项目配置提供 10 套建筑缩略图：灯塔、楼阁、温室、工厂、天文台、风车、书塔、火箭基地、城堡、画室。默认自动分配，优先未使用样式，超过 10 个项目时从使用最少的样式中随机选择。分配结果保存在 studio.json 中，刷新、重排、删除其他项目不会改变已有岛屿；手动选择允许重复。选择自动模式后保存会固定结果。

打开「系统配置 → 执行器与模型 → 快捷导入」，手动选择已安装的 CLI，再填写执行器名称、模型 ID、思考强度和权限。Codex 可从「Sol 6.2 · 高」或「Astra 6.2 · 高」模板填入参数后再修改。模型和思考强度留空时使用 CLI 默认值。Codex 和 Claude Code 的程序路径可留空使用运行时默认程序，Antigravity 需要填写 CLI 的绝对路径。

每次导入创建独立的执行器。全局默认在本页设置，已有项目的规则绑定保留，新建任务时仍可显式选择执行器。展开已登记的执行器可以复用参数，再另存为一套配置。

生成资产与提示词保存在 public/art/islands/，图片打包在本地前端中，刷新页面即可更新，不需为美术更新重启后台。构建前若修改 WebP 文件，运行 npm run build 重新打包。

## 居中详情与关联任务列表

工作台按项目、消息接收、网关、大模型执行器、排队、结果与待答复分区排列，不要求流程固定从左向右。图标按主次缩至 36–48px；区域展示真实的执行、排队和待答复状态。跟踪任务时突出关联区域和当前节点，区域位置保持稳定。点击节点或任务后打开居中原生 dialog；执行输出同样居中，支持 Escape 和遮罩关闭。首页的「任务列表」进入统一任务管理。

任务列表自动分页读取全部执行历史，再从已有 `why` 事实中提取每轮的规则与事项 lane。相同事项、已验证的话题绑定或同项目同执行器的相同会话归在同一任务；不根据同名标题、相似正文或仅相同项目猜测关联。原执行事实不改写。关联未确认时保留独立记录并明确标注。

任务列表默认显示全部状态。业务任务和后台运行的列表用左右分栏，左侧切换任务，右侧查看「结果与待办」「原始需求」和「执行记录」。有待答复的问题时可在右侧提交选项或文字，切换任务会保留当前窗口里的草稿。筛选「待你处理」时，已答复的任务会离开筛选结果。

每个任务可展开全部轮次，支持项目/状态筛选、文本搜索、继续已登记话题、停止尚未结束的轮次、处理事项的待答复，以及查看原始结果和输出。状态筛选采用当前任务聚合状态，不因存在历史完成轮次而把仍在执行的任务列作已完成。关联读取失败会提示并允许重试，不把部分历史冒充全部结果。

### 流转速度与任务记录

任务统一按「需求确认 → 项目归属 → 执行处理 → 结果验收 → 结束」展示阶段，阶段内显示确认中、待你确认、待你选择、待执行、执行中、待你处理、你处理中、待验收、验收中等状态。发起、确认通过、分配项目是流转记录，不额外卡住执行。所有新任务（包括已选项目）先确认目标；本人可明确勾选已确认，或由隔离的只读识别通道判断，不清楚就结束本轮并等待补充。已有话题续聊沿用归属。

只有统一完成判定给出 `ready_for_acceptance` 才进入待验收；旧轮次没有目标检查报告时是「执行处理 · 结果待核实」，有剩余工作是「待继续处理」，不得因正常退出自动验收。本人接手完成后可附说明提交验收。验收通过后才关闭，关闭结果区分已完成、已取消、无需处理；首页完成数只计本人验收关闭的任务。

「退回修改」沿原话题派发，保留验收意见并标记返工。「调整目标」先回到需求确认，明确确认后才沿原项目执行。「重新打开」恢复已关闭任务并沿原话题派发；没有 Studio 话题的外部任务重新打开后由本人接手，需要 AI 继续时使用原来源。问题卡片通过既有回答接口接续；多个问题须逐项回答。停止执行和关闭任务是不同操作。

暂停只用于当前没有运行、未答问题和待复查的任务，不停止 Worker，也不暂停整个项目规则。暂停、接手、关闭期间拦截 Studio 同话题续聊；外部来源产生新轮次时按真实执行状态重新显示，旧操作保留在历史。验收按钮绑定页面所见记录，记录变更必须刷新查看后再操作。离线时禁用人工流转操作。

人工操作追加到 `studio.db` 的 `gateway_facts`（`workflow:`），来源消息的确认和归属过程仍使用 `request:` 事实；不修改 Hub 的业务事实或升级迁移文件。`GET /api/tasks/:run` 读取完整任务与操作记录，`POST /api/tasks/:run/actions` 接收动作及所见版本，不接受任意阶段、目录或执行器。列表、详情、首页状态和统计共用 `workflowFor`，机器判定共用 `taskStatusOf`。

画布以留白分区、小图标和曲线呈现实际路径。流转默认每段 4 秒，可选 8 秒或 2 秒并保留本机偏好；悬停或键盘聚焦任务标签会暂停，点击打开居中详情。暂停按钮冻结标签的位置，底部任务动态和任务列表提供固定入口。动画只说明已观察到的状态变化，不代表任务完成百分比；回放有单独标识。

任务详情可按关联轮次展示左右对话，也保留原始需求、结果、时间线和执行信息。Studio 自管接单程序在 Codex 和 Claude 执行期间增量保存公开助手消息及操作状态；仅连接已有引擎时需要该接单程序启用存档。其他执行器、旧轮次、远端执行器及存档失败时不能保证留存。未存档时临时输出仍限最近 3 次尝试、每个文件末尾 24 KB；未上报或已清理的过程不会补写为事实。界面不显示模型推理或命令内容。

### 业务任务与后台运行

概览的「运行中」与 Hub 派单数取自实时轮次，项目卡片按项目汇总活跃轮次和待验收工单。共享执行器按接单程序统计占用，同一个接单程序下的多套执行器配置共用容量。工单看板可切换到「后台运行」查看后台记录。

首页读取历史分页，避免高频采集挤走业务任务。任务动态按话题、事项、会话以及事实日志中的派生事件关联聚合；后台采集父轮次不参与业务聚合，避免把不同消息合成一个任务。动态显示当前阶段、执行器明确反馈、最近结果，原始需求与产物链接可在居中详情查看。

### 弹窗与网关拦截

任务详情首屏呈现本轮结果、当前反馈与状态，完整最终反馈、原始需求、过程、时间线和执行信息分区查看；历史领取模型未记录时明确标注，不拿当前配置代替。固定底部操作区、原生焦点约束、Escape 关闭、键盘标签切换和窄屏滚动共用一套浅色样式。

`done` 只说明一轮交回结果，轮次时间线保留“本轮结束”；任务列表、详情和首页统计使用上文统一生命周期。缺少目标检查报告时显示“结果待核实”，有答复、复查或后续执行时优先显示实际进展。保留原结果正文，不依据文字关键词改写历史事实或自动重派业务。

网关弹窗的提示词与实际分类进程共用 `src/gateway-policy.mjs`。`gateway.blockedTerms` 是可选字符串数组，默认不拦截；每行一项、最多 100 项，每项 1–200 字，消息包含任一词即在识别和派发前返回 422，英文不区分大小写。预览使用当前未保存草稿，不提交任务；保存后热更新，重开与重启后保留。新任务、明确项目和已有话题续聊都检查；关闭智能识别不关闭拦截。已成功提交的同 ID 消息仍按原去重结果返回，不追溯取消执行。外部事件、通道回答与定时复查不经过 Studio 消息入口，不受此功能限制。它是明确的文本匹配规则，不是语义安全分类器。

隔离真机表单验收：`python client/tests/dialog-e2e.py`。脚本在临时目录启动 Studio 和真实 Hub，验证添加项目、附加流程改名、换目录后规则身份隔离、网关规则持久化和拦截提交；识别模型用替身，不消耗模型额度，退出清理自建进程与目录。
